# 敬語ボタン 0.1.9

## 日本語

初回セットアップで「メッセージで使う名前」を専用のページに分け、入力した名前が実際の返信でどう使われるかをその場で確認できるようにしました。あわせて、アプリの改善に使う内部の計測を作り直しています。

- 名前の設定を独立したページに変更。これまではサインインの下に重ねて置かれていたため、登録フォームの一項目のように見えていました。名前は書き換えた文章の署名に使われる、あなた自身についての唯一の設定です
- 名前を入力すると、その名前を使った返信の下書きがその場で表示されるようになりました
- セットアップの各ページにマスコットのアニメーションを追加しました
- 書き換えの計測を作り直しました。これまではボタンを押した回数そのものを数えておらず、失敗した書き換えや、続けて別のボタンを押して打ち消された書き換えが記録に残っていませんでした
- ボタン・カスタム指示・返信・再生成・追加指示の5種類を区別して記録するようにしました。これまでは4種類が同じ扱いだったため、どの操作が使われているのか分かりませんでした
- 書き換えが失敗したとき、「書き換える文章が見つからなかった」のか「生成そのものが失敗した」のかを区別して記録するようにしました

内部の計測に、書き換えた文章そのものや入力内容が含まれることはありません。

## English

Setup now asks for your name on a page of its own, and shows you what that name looks
like in a real reply as you type it. The measurements we use to improve the app have also
been rebuilt.

- The name question is now its own page. It used to sit stacked under the sign-in, where
  it read as one more field of the signup form rather than as the name every rewrite gets
  signed with — the one setting on that page that is about you
- Typing your name now draws a sample reply using it, so you can see how it will read
- Setup pages now carry an animated mascot
- Rewrite measurement has been rebuilt. Until now nothing counted a button press, so a
  rewrite that failed, or one you cancelled by pressing a second button, left no record
  at all
- Buttons, custom instructions, replies, regenerate and follow-up instructions are now
  recorded as five distinct actions. Four of them used to be indistinguishable, so we
  could not tell which parts of the bar people actually use
- When a rewrite fails, we now record whether nothing could be found to rewrite or the
  generation itself failed — opposite problems that used to look identical

None of these measurements include the text you wrote or the text the app produced.

## 简体中文

首次设置现在会在独立页面询问你的名字，并在你输入时即时显示该名字在真实回复中的样子。我们用于改进应用的内部统计也已重建。

- 名字设置改为独立页面。此前它叠放在登录下方，看起来像注册表单里的又一个字段，而不是每次改写都会用来署名的名字——那是该页面上唯一关于你自己的设置
- 输入名字后，会即时生成一段使用该名字的回复草稿，让你看到实际效果
- 设置页面新增了吉祥物动画
- 重建了改写统计。此前我们并未统计按钮被按下的次数，因此失败的改写、或被你接着按下的另一个按钮取消掉的改写，都没有留下任何记录
- 按钮、自定义指令、回复、重新生成、追加指令现在作为五种不同操作分别记录。此前其中四种无法区分，我们因此无法得知工具栏的哪些部分真正被使用
- 改写失败时，现在会区分「找不到可改写的文字」和「生成本身失败」——这是两个相反的问题，此前看起来完全一样

这些统计不会包含你写的文字，也不会包含应用生成的文字。
